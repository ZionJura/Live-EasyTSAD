# Leaderboard 前端展示方案

## 设计目标

以「研究者可以快速选方法，也可以深入核对实验」为主线。沿用 EasyTSAD 的实际领域：时间序列异常检测。当前不引入预测任务，也不把其他平台的分数当作本仓库实验结果。

参考来源（2026-11-04 查看）：

- [Arena Leaderboard](https://arena.ai/leaderboard)：借鉴持续可见的侧栏导航、留白、清晰的主次层级、排名表和分类探索；不使用 Arena 的品牌标识、模型投票分数或 Elo 规则。
- [Arena Text 排名详情](https://arena.ai/leaderboard/chat/text)：借鉴紧凑行结构、模型主信息与辅助信息分层、过滤与排序。
- [OpenTS 多变量检测排行榜](https://decisionintelligence.github.io/OpenTS/leaderboards/#multivariate_detection)：借鉴任务、数据集、指标、算法的筛选维度与单数据集最佳表现概念。OpenTS 支持奖牌计数及加权排名；本方案默认使用明确的单指标宏平均，未复制其奖牌权重算法。
- [OpenTS 多变量检测结果表](https://decisionintelligence.github.io/OpenTS/result/#multivariate_detection)：借鉴排名与结果分离、矩阵核对和结果导出，降低检查各数据集结果的成本。

## 仓库如何支撑页面

| 现有模块 | 对应前端概念 |
| --- | --- |
| `DataFactory/TSData.py`、`MTSData.py` | UTS / MTS 任务入口 |
| `TrainingSchema/`、`TSADController.run_exps()` | naive、all_in_one、zero_shot、zero_shot_cross_ds、mts |
| `Evaluations/Protocols/` | 独立的指标与协议，名称和参数需要明确 |
| `TSADController.do_evals()`、`PathManager.get_eval_json_avg()` | 数据集平均评测结果 |
| `Summary.to_csv()`、`gen_site_table.py` | 已有导出与排名思路，新界面使用结构化 JSON |
| `Methods/` | 方法名、类别、源码入口 |

当前仓库没有独立 Web 应用、可用榜单 API 或可发布的实验快照，因此新增 `leaderboard/`，隔离前端依赖和训练环境。现有 Python 与 MkDocs 逻辑不需要改动。

## 页面布局

桌面使用左侧 224px 常驻导航，主区最大宽度 1510px。主页面依次是：

1. 轻量顶栏：当前位置、演示 / 导入状态、GitHub。
2. 标题区：榜单定位、可复现理念；以时序波形和异常区间作装饰。
3. 统计条：当前范式下方法数、所选数据集数、可切换指标数、快照日期。
4. 任务 Tab：多变量 / 单变量异常检测。
5. 主筛选：训练范式、指标、数据集多选。
6. 视图栏：排行榜 / 结果矩阵；分享与 CSV 导出。
7. 排名表 + 右侧解释区；矩阵模式扩为全宽。
8. 数据来源与排名规则摘要、导入入口。

移动端导航收进弹窗，筛选变为两列，排名表在容器内横向滚动；矩阵方法列固定，保留核对上下文。右侧解释区移到表格下方。

## 视觉语言

| 元素 | 方案 |
| --- | --- |
| 画布 | 冷白 `#f7f9fd`，白色侧栏与数据表，给数据足够留白 |
| 主色 | 深蓝 `#19375c` 承载标题、主按钮和榜首卡；蓝色 `#3467ab` 承载导航、筛选与普通分数 |
| 荣誉色 | 哑金 `#b48a38`、浅金底 `#fbf5e8`；深蓝卡片上使用亮金 `#edcc82`，保持文字对比度 |
| 字体 | DM Sans + Noto Sans SC；系统字体兜底；数值等宽对齐 |
| 边界 | 细描边、小圆角；仅弹窗、浮层有明显阴影 |
| 榜单 | 第一名用浅金底、金色排名与分数条；普通行用蓝色分数条；勾选态用浅蓝，与榜首状态区分 |
| 图形 | SVG 时序装饰；对比使用直观的同尺度条形图 |

不在首屏堆叠雷达图、装饰性大图或重复统计卡。让方法名称、分数与评测条件占据主要注意力。

配色以白色为大面积基底，蓝色组织结构，金色突出荣誉。大致视觉占比为白色 80%、蓝色 15%、金色 5%，避免所有高亮争夺注意力。矩阵普通数值采用浅蓝热度，单数据集最优结果采用金色描边和标记；金色仅表示最佳表现，不暗示统计显著性。方法比较图使用蓝色与金色的不同明度，同时保留图例、方法名和数值。

## 核心视图

**排行榜**：选择框、排名、方法（名称 / 类型）、当前指标的综合分数、覆盖率、最优数据集数量、详情。分数条固定 0–1。右侧「当前领先」说明当前条件下的榜首，下方列出各数据集最佳方法。搜索不会把「当前领先」改成搜索结果第一项；它始终针对完整评测范围。

**结果矩阵**：方法为行、数据集为列，另附综合均值。只展示当前选中的一种指标；单元格浅色热度辅助浏览，最佳值有明确标记。指标保持单一，避免把多种协议混在一张难以横向阅读的超宽表里。点击方法可一次查看其三种指标。

**方法详情**：描述、源码、当前条件下排名 / 均值 / 覆盖率；所选数据集 × 三种指标的小矩阵。后续可补论文、年份、超参数和复现命令。

**方法对比**：勾选 2–4 个方法后出现底部操作条；按数据集分组展示条形图和原始数值。优先回答「哪个方法适合哪个数据集」，不使用面积难以比较的默认雷达图。

**评测说明**：具体指标类与参数、排名规则、缺失值策略、训练范式和实验可复现条件。无需离开榜单。

## 数据真实性与排名

演示状态在顶栏、快照、页脚、详情、对比和 CSV 中标记。示例中出现某方法与 MTS / Zero-shot 组合，仅用于展示交互，不表示仓库实现实际支持该组合。真实数据导入后只显示实际记录。

宏平均要求所有所选数据集都有当前指标，防止少跑困难数据集获得不合理高排名。缺失值显示「—」，数据集列仍保留已有结果。单指标、单训练范式排名；不把调整后的 F1、未调整的 AUPRC、不同实验范式混合成不透明总分。暂不展示没有实验依据的置信区间、榜单涨跌和推理成本。

## 下一步接入

1. 用导出脚本完成一批同协议、同预处理的真实实验快照，审核方法支持范围和数据集版本。
2. 为快照增加实验清单：commit、数据版本、随机种子、训练 / 测试比例、margin、协议参数、运行环境、时间与失败原因。尤其注意 avg.json 未保存 EventF1PA 的 base。
3. 发布时从静态 JSON 或 API 加载经审核快照，加入加载 / 失败 / 空数据状态；当前只做显式本地导入，避免把演示分数误认为线上榜单。
4. 后续可扩展 event-wise / delay 指标、显著性比较、运行成本、论文和模型提交审核；每项需先确定评测语义再增加 UI。

本轮不部署网站，不改动训练流程，不声称演示分数具有科研结论。
