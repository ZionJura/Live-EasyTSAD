01 · 先分清三个东西

Harness 是给模型组织上下文、执行工具、保存会话与控制生命周期的程序。模型负责判断和生成；Harness 负责把判断落实为可观察、可恢复的行动。当前 TSAD 默认模型为 deepseek-v4.1-flash，常驻聊天 Host 与流程 CLI Worker 使用同一模型配置。

原版 DeepSeek Harness

仓库 EasyTSAD/tsautoreproduce-harness 是全插件 Cordis 系统，源码版本见根 package.json。它提供通用 Agent 内核与多种产品界面。

我们的 TSAD Harness

EasyTSAD/Harness 把论文、适配、训练、评测、报告与榜单串起来。实验状态、GPU 和产物有独立领域语义，不应该交给聊天记录代管。

版本边界：本报告讲解仓库保存的源码；实际 TSAD Host 固定使用 npm 0.2.2-rc.1。源码目录与已发布包的能力存在差异：npm rc1 没有发布原生 Team 包，不能注入 agentTeams。当前 TSAD 用项目内的小型持久任务板适配器提供 Team 功能；它是这项能力的兼容实现。原版 Team 章节与完整配置目录保留作源码教学参考，不能视为 rc1 安装包均已包含。历史安装的 Python SDK / runtime 为 0.2.1rc2；旧安装可能缺少这里的 API 或使用不同的参数。先检查版本并成对固定 SDK、runtime 与插件，不能只按新版源码写客户端、继续运行旧二进制。

初学者按 02 → 03 → 04 → 05 阅读；要扩展 TSAD，再读 07 → 08 → 11 → 12。参数查第 10 节；完整插件配置可在第 14 节离线搜索。

02 · 从一条消息理解架构

输入与交互Web、SDK、终端把用户消息、Slash 和审批传给应用入口。
Agent 与 SessionAgent 管理循环、队列和取消；Session 保存事件与上下文历史。
模型与工具LLM provider 发起请求；工具服务校验和执行；失败回到会话。
持久化与投影事件写入日志；Goal、Todo、子 Agent 目录和 UI 从事件形成投影。

一次 Agent turn 的核心循环

  1. 接收输入并持久化 inbox；轮到它时开始一个 turn。
  2. 组装系统提示、会话历史、技能目录、工具 schema 与运行上下文。
  3. LLM 返回文本或工具调用；执行器调用对应 provider，记录结果。
  4. 工具结果回到下一步模型请求；直到正常结束、预算终止、错误或用户取消。
  5. 持久化事件、更新投影并发出通知；Goal driver 可在条件满足时调度下一轮。

插件依赖由服务可用性决定，YAML 行顺序主要帮助阅读。不要通过改 Agent loop 塞入实验业务；新增能力应挂在服务、事件、工具、命令和 UI 插件扩展点。

依据：docs/architecture.md；packages/core/agent；packages/session；packages/bundle/base/cordis.patch.yml。

03 · Cordis、Plugin、Bundle 与 Profile

概念负责什么例子
Context / Service服务注入、事件与生命周期；依赖未满足时插件等待。ctx.subagents、ctx.commands
Plugin导出 name、inject、Config、apply 或 Service；注册能力与清理。goal、web-fetch-http、command-goal
Bundle有序 patch 的打包单位，提供配置层。dsh-base、dsh-web-app、dsh-sdk-app
Profile可启动应用的持久组合，保存依赖清单与用户 patch。web、sdk、headless、sdk-minimal、acp

覆盖规则一定要理解

Bundle patch（按 profile manifest 的 bundles 顺序）
→ $DSH_HOME/profiles/<profile>/cordis.patch.yml
→ $DSH_HOME/cordis.patch.yml
→ 本次启动的 --patch（按命令行顺序）
config 是整块替换，不能假设深度 merge。 后层按 row id 定位；给某行写 config 时，应重复该行需要保留的全部配置。禁用某个 service 也可能让依赖它的插件无法激活。

sdk-minimal 是独立显式配置树，不是给 dsh-base 再裁剪一层。它提供 shell、read_image、工作目录、会话和自动压缩，不等于完整 SDK 加上全部工具。

# 只查看配置；不需要发起模型请求
export DSH_HOME="$PWD/.dsh-guide-home"
dsh --profile sdk --dump-default-config
# 自定义 profile 使用一个全新的名字，避免覆盖已有 profile
# 此命令会初始化并启动应用，不是 dry run
dsh --profile research-lab --from-default-profile web --no-open

配置中动态表达式使用 !!js，不是 !js。仅受支持的 config 和 disabled 字段执行表达式；不要把密钥写进 YAML，使用环境或 credentials 服务引用。

依据：apps/cli/README.md（Profile 与启动规则）；packages/bundle/base/cordis.patch.yml；docs/cordis-primer.md。

04 · 从零运行一个完整 Harness

A. 使用仓库源码

cd EasyTSAD/tsautoreproduce-harness
# 源码开发要求 Node >=24.9 与 pnpm；安装会写依赖目录
pnpm install
pnpm run build:artifacts
export DSH_HOME="$PWD/.guide-home"
# 在终端预先设置 DEEPSEEK_API_KEY；不要写入仓库
pnpm dsh --profile headless "用一句话解释时间序列异常检测"
pnpm dsh web --no-open

构建和配置查看不调用模型；发送提示词会调用模型。Web 的实际启动参数以 pnpm dsh web --help 为准。不要直接运行内部 package bin 或绕开 profile 启动应用。

B. Python 持久会话示例

配套文件：guide-examples/sdk_chat.py。使用与 0.2.2-rc.1 配套的 SDK/runtime 环境；若开发源码 Python SDK，请按原版 python/development.md 构建和安装 runtime 产物。

python EasyTSAD/Harness/docs/guide-examples/sdk_chat.py   "先解释要如何接入一篇异常检测论文"   --home /absolute/path/to/guide-home   --workspace /absolute/path/to/Live-EasyTSAD
# 保持同一个 home 和 session id，显式恢复已保存历史
python EasyTSAD/Harness/docs/guide-examples/sdk_chat.py   "继续刚才的讨论" --resume   --home /absolute/path/to/guide-home   --workspace /absolute/path/to/Live-EasyTSAD

SDK 用 stdio NDJSON JSON-RPC 与匹配的 bundled dsh 通信。显式 home 是必需条件；不要依赖隐式读取 ~/.dsh。cwd 是 Agent 工作区；runtime_cwd 是子进程自身工作目录。

C. 不运行模型的配置练习

dsh --profile sdk   --patch /absolute/path/to/guide-examples/research.patch.yml   --dump-default-config

配套 patch 演示完整源码 profile 的深度 2、最多 4 个活跃子 Agent、32 个 Goal rounds 与 Team 配置；其中原版 Team 示例需要包含 Team 包的源码构建，不适用于 npm rc1。当前 TSAD 使用本地任务板适配器。这些是教学选择，原版默认值见第 10 节。

05 · Session、队列、流式输出与恢复

Session 是持久事件日志，不只是一个 messages 数组。用户输入、模型输出、工具执行、Goal、命令与子 Agent 创建事实都要记录；投影是从日志得到的当前读模型。

行为正确语义
start_session(id)创建惰性句柄，不代表已恢复磁盘历史。
resume_session(id)恢复 root 历史，修复中断的末轮；不存在、不兼容、被占用就报错，不偷偷新建替代会话。
run(input, on_notification)普通输入从持久 inbox receipt 观察到整棵 Agent 树空闲；根最终文本不会被子 Agent 回答覆盖。
queue排入后续轮次，不强行打断当前思路。
steer向正在进行的流程注入纠正，原生服务处理取消和下一步。
stop停止当前轮并保留排队消息；停止聊天与停止 GPU 实验是两种领域操作。
reconnect恢复历史/游标与投影；不能因为 HTTP 超时就自动重发有副作用的请求。
恢复 Session 不会重建 shell、浏览器和其他外部进程。已启动训练需要由 TSAD 任务服务通过进程、锁和产物检查恢复管理。SDK 不能直接恢复子 Agent Session；应恢复它的 root，再走子 Agent 生命周期和地址控制。

要有真正的流式体验

Web 的 session follow 同时提供持久事件与 assistant live chunks；客户端已有尾页修复和断线重连。SDK on_notification 可接收 root 与已发现 descendants 的通知，但 RunResult.events 仅包含 root 事件。不要把任意通知当作文本 delta，应按类型解析。

消息有 requestId 才能在重试、重连和并发点击时去重；接收成功是“已入队”，并不等于训练成功或 Agent 已结束。

依据：python/sdk/README.md；packages/sdk/server/README.md；packages/api/session-controller/README.md。

06 · 工具、搜索、抓取与 Skills

一个工具应包括定义、provider、消费者和失败语义。模型看到的是工具 schema；真正执行依赖宿主服务。启用 tool-web 却不配置可用 search provider，不会凭空获得搜索能力。

搜索与网页抓取

base 默认 searchProvider 为 deepseek-search-api，fetchProvider 为 http。搜索使用 DeepSeek 搜索 API 凭据；兼容 OpenAI 的模型代理 key 不保证可用于该搜索服务。HTTP fetch 可独立工作。

抓取有超时、响应字节、正文长度、重定向上限及网络目标检查。工具输出是外部资料，需要结合论文/官方源码核对。

MCP

MCP 适合把 Python 的论文、任务、日志和实验操作暴露成模型工具。TSAD_TASK_DIR 等上下文由宿主传给工具进程。启动超时和单工具超时需要区分；握手成功不代表训练成功。

Skills 是复用流程知识的介质

Skills 提供可发现元数据与按需加载的详细说明，不是后台训练任务，也不是强制权限隔离。当前 TSAD 仅保留四个通用技能：fetch-repository、research-hyperparameters、research-interface、research-environment。IMPLEMENT 与 DIAGNOSE 使用固定提示词；阶段协调和结果汇总由 Python 控制器执行。

项目根目录/
  .agents/skills/tsad-reproduction-review/SKILL.md
# 也支持项目 .dsh/skills、用户 $DSH_HOME/skills 与 ~/.agents/skills
# 教学模板在 guide-examples/SKILL.md；复制后按项目标准调整

扫描根依次包括项目 .dsh、项目 .agents、自定义目录、用户 DSH、用户 agents，再加可选 bundled root。provider 配置 includeDefaultRoots:false 可用于只扫描明确的自定义目录；catalog 与正文加载是不同步骤。

创建你的第一个原生命令插件

配套 guide-examples/command-plugin 导出 name、inject 与 apply，调用 ctx.commands.register 注册只读 /hello-tsad。使用新的 Web profile 安装本地包后，再应用 command.patch.yml。

# 先用全新 profile 初始化；用 Ctrl+C 退出后执行安装
export DSH_HOME=/absolute/path/to/guide-home
dsh --profile research-lab --from-default-profile web --no-open
dsh plugin --profile research-lab add file:/absolute/path/to/guide-examples/command-plugin
dsh --profile research-lab   --patch /absolute/path/to/guide-examples/command.patch.yml --no-open
# 在该 Web 的输入框执行 /hello-tsad
Python SDK 的 native slash adapter 只支持明确的内置命令集合。给 registry 注册自定义命令，并不会让 SDK 自动分派它。自定义 /tsad 需要我们自己的 Host bridge 或 Web 原生 command adapter；不要误把 SDK 未识别的 slash 当作已执行命令。

依据：packages/web；packages/mcp/mcp-client；packages/skill/skill-filesystem/src/index.ts；packages/interaction/commands/README.md。

本节解释保存源码中的原版能力。固定的 npm rc1 没有发布原生 Team 服务；当前 TSAD 的 Team 是本地 team-adapter.mjs，原生子 Agent 仍由 DSH 提供。

07 · 子 Agent、Fork 与 Team 的区别

能力适用场景真实限制
spawn 子 Agent新角色、独立任务与上下文，例如论文研究、适配和评测监督。遵循深度与活跃并发上限；共享目录时必须划定写入所有权。
fork 子 Agent继承父上下文的短期独立分析，可复用上下文。默认 fork 委派仍为 one-shot；不应假设能任意选择不同模型后继续对话。
continuable 子 Agent常驻监督角色、用户可进入的专家会话。通过原生 subagents/prompt 续聊；需要有效地址和活跃树所有权。
Team同一 subagent root 下共享任务板、认领与协作。默认关闭；maxTasks 是任务板容量，不是并发 Agent 数；旧 maxMembers 等配置已经移除。

模型工具 subagent、subagent_fork 选择 provider；send_message 用于同树成员沟通。原版 Web 显示子 Agent 目录、状态、耗时和 token 使用量；continuable 子会话有正常 composer 和独立 Stop；one-shot 与 unknown 显示只读。

TSAD 聊天与流程 Worker

普通聊天由常驻 Host 会话处理，可以继续发消息、queue、steer 和停止当前回复。用户明确请求复现时，Python 控制器按阶段创建独立 CLI Worker；每个 Worker 有单独的进程、持久会话、阶段绑定和日志，binding.kind=cli。选择会话可查看历史并发送后续消息；停止一个 Worker 不应影响其他任务。

FETCH 使用一个来源发现 Worker；RESEARCH 同时运行超参数、接口和环境三个 Worker。IMPLEMENT 读取三份研究产物；DIAGNOSE 只在具体执行问题出现时运行。训练、评测、进程状态、阶段转换和完成判断由控制器负责，无需额外协调、监控或报告技能。

依据：packages/subagent/subagent；packages/subagent/tool-subagent；packages/team/agent-team/src/index.ts；packages/client/ui-subagent/README.md。

08 · Goal、Plan 与 Todo 各司其职

Goal：跨多轮的目标状态

有 active、paused、blocked、complete，记录 objective、revision、roundsStarted 与轮次上限。driver 在整棵树静止且无竞争输入时启动下一轮。恢复保存状态后，需要 /goal resume 重新赋予自动推进权。

Plan：先讨论再执行

/plan 进入；/plan off 退出；带正文通过 steer 提交。计划审查依赖 user-question 交互通路；改变计划模式不改变权限。

Todo：当前工作的结构化清单

todo_write 更新实现过程的任务清单；可显示多篇论文的高层计划，但它不应成为批次任务、GPU 锁或重试记录的唯一存储。

TSAD 一键流程：可验收的目标

Goal 的完成条件应该读取任务服务的执行完成状态与榜单 generation，不依据 Agent 自述“完成”。批次内每篇论文的生命周期要独立持久化。

/goal 复现这批论文，并完成配置审查、全量评测和榜单同步
/goal pause
/goal resume
/goal edit 为每篇论文补充官方配置和实际配置的差异
/goal clear
/plan 分析如何处理分数与标签长度不一致
/plan off
/compact
/permission workspace-write

SDK 的 Goal creation / resume 等待自动 rounds 的终止与收尾，而低层 session/wait 可能在 rounds 之间返回。用户暂停不等于失败；blocked 不等于静默重试。不要另起一个 Python 循环与 Goal driver 对同一任务同时重启。

依据：packages/goal/goal/src/index.ts；packages/goal/goal-round-driver/src/index.ts；packages/sdk/server/README.md。

09 · 界面实现与真实 API 边界

入口已有能力需要补充的部分
原版 WebReact 18、Vite 6、Cordis 客户端插件、Lexical 输入、Typert Remote；原生会话树、Slash、steer/stop、审批。TSAD 任务、阶段、日志、逐曲线指标和榜单面板。
DesktopElectron 载入同类客户端；IPC 代替浏览器 HTTP transport，含宿主文件打开等功能。本轮无需引入桌面打包。
Python SDKstdio JSON-RPC；持久 Session、run 与通知、四组内置 native slash、审批与问题回调。协议没有通用 cancel/session-close/steer/custom slash API；不能用它直接覆盖完整 GUI 控制需求。
headless一次启动、一次提示词、多模型 steps、完成后退出，支持 JSON 事件流。不是常驻交互服务；当前 TSAD legacy worker 不能在 stdin 关闭后继续接收消息。
TUI历史原版 packages/ui/tui 使用 pi-tui；本项目恢复固定源码版本 7248b5ec8f8769f882f12fd521504fa48e97bcf3，保留 BSD-3-Clause 许可证与 pi-tui 0.80.7 补丁。复用原版终端组件，由 Node 客户端经现有控制 API 接入同一个 Host；阶段、资源和进程管理仍由 Python 控制器负责。

我们的排行榜是 React 19 / Vite 7，不能直接把原版依赖 React 18 单例的客户端插件当成普通组件 import。当前保留独立排行榜，Harness 只提供原版 pi-tui 组件适配的 Node TUI，通过稳定 TSAD API 调用 Host。常驻 Host 使用 dsh-base 加原生会话控制后端，不加载 dsh-web-app、浏览器 UI 或 Webserver。本节 Web / Desktop 描述原版能力，本项目不启用这些页面。

审批与问题不能丢

SDK approval_requests:true 后，宿主必须同时读取并回复 approval/request；只允许 allowed-once / rejected / cancelled。断线与非法回复默认拒绝。原生 ask_user_question 使用 on_user_question 或协议 capability，需要真实 UI 来呈现问题，不能未经用户选择自动批准。

依据：apps/web/package.json；packages/client/ui-conversation/README.md；packages/api/gateway/README.md；packages/sdk/protocol/README.md:141；本地 tui/vendor/PROVENANCE.md 与固定版本的 packages/ui/tui。

11 · 当前 TSAD 自动复现流程

FETCH → RESEARCH → IMPLEMENT → EVALUATE → REPORT → DONE。RESEARCH 分为三个并行分支；DIAGNOSE 是执行异常后的条件分支，修复后继续。没有强制的 SMOKE、人工审核或独立报告写作阶段。

阶段 / 技能工作实际产物
FETCH
fetch-repository		发现论文与官方仓库；Worker 给出来源证据，脚本下载论文并克隆仓库。没有官方仓库则标为 unsupported。方法目录下 paper/、upstream/、reproduction/source.json 与 commit/tree 记录。
RESEARCH / hyperparameters
research-hyperparameters		提取官方参数、默认值与文献证据，不依据测试分数调参。config.toml 与 reproduction/hyperparameters.json，参数相互对应。
RESEARCH / interface
research-interface		建立官方输入、输出到 EasyTSAD 的映射，明确窗口、维度、分数方向和时间对齐。reproduction/adapter.yaml，包含 source、target、align、evidence。
RESEARCH / environment
research-environment		研究依赖；脚本生成锁文件、执行 uv 安装并验证导入。environment/pyproject.toml、environment/uv.lock、reproduction/environment.json 与安装日志。
IMPLEMENT固定提示词读取三个分支产物，复用 upstream，接入方法接口，读取或修正已有参数。方法源码、适配器与 config.toml。
EVALUATE / DIAGNOSE原有实验流程真实训练、评测；异常时依据进程、日志和源码定位后修复。真实进度、逐曲线指标、运行记录与诊断证据。
REPORT → DONE读取现有 canonical 评测结果，返回文件引用与数据。原始 avg.json、all.json；无需额外生成 Markdown 报告。

流程 Worker 的 MCP 连接

每轮 CLI Worker 启动前，控制器先预启动该角色的受限 MCP 服务，等待就绪后使用 loopback Streamable HTTP 连接。服务只监听 127.0.0.1，端口与秘密路径每轮随机生成；冷启动导入不占用原版客户端的 60 秒 MCP 握手窗口。服务与 CLI 分别记录 PID、身份和日志，随本轮结束而停止；/ps 和 API 展示会移除秘密路径。

固定 rc1 的 Team 兼容边界

聊天、Session、Goal 与子 Agent 使用固定 npm rc1。该版本未发布原生 Team 包，TSAD 提供项目内的持久任务板：DSH_HOME/tsad-team-boards.json 原子保存，每个会话树最多 256 条任务；支持启用、读取、创建、带 revision 检查的更新、依赖校验与领取/完成操作。Lead 可调用 tsad_team，客户端从 snapshot.team 读取同一状态。健康接口标明 teamImplementation: tsad-adapter。任务板仅辅助对话；实验调度仍由 Python 控制器负责。

查看正在执行的工作

TUI 用简洁状态行展示当前任务、研究分支和进度；其他信息通过 Slash 命令查看。训练条读取实际 epoch 或训练计数，评测条读取实际完成数量；未收到进度时显示等待记录，不按时间推算百分比。输入 /ps [job] 可查看已登记的 Agent、环境安装和评测进程：PID、启动时间、命令、工作目录、GPU、日志路径、脚本路径及脚本内容。

指标只有一个来源

分数直接读取既有评测流程生成的 Results/Evals/.../avg.json 与 all.json，分别表示数据集汇总和逐曲线结果。运行中结果标为 provisional；该次评测完成后标为 final。API 返回路径和原始指标数据；REPORT 无需复制指标到新文件，也不引入第二套汇总公式。低分本身不是执行异常或调参依据。

四个技能与固定提示词均为通用方法流程，不按算法家族增加分支技能。Python 仍是唯一的阶段、资源和进程所有者；Goal、Todo、Team 可辅助对话，不承担实验状态存储。

13 · 常见误解与验收

只把 trim.patch.yml 的 disabled 改为 false，为什么还是不能完整对话？

headless 应用入口仍是单次运行；工具能力与交互 transport 是两件事。需要常驻 Host、持续会话和输入/流式/取消接口。

为什么搜索报凭据错误，模型却能对话？

模型代理和搜索 provider 是两个服务，key、base URL 和可用性要分别检查。HTTP 抓取也不是搜索替代品。

看到子 Agent 日志，为什么不能发消息？

可能是 one-shot、unknown、外部 provider 或树所有权已失效。进入历史不代表具有继续执行权；UI 应明确只读。

开启 Team 之后是否自动并发复现全部论文？

Team 管理共享任务，不代替实验调度。maxTasks 256 是板容量，maxActiveSubagents 8 是默认活跃上限，GPU 并发由 TSAD 配置控制。

HTTP 请求超时后能立即再点一次吗？

超时不是回滚。用同一 requestId 查询或恢复接受状态，避免生成重复任务、重复训练或重复消息。

DONE 是否证明论文复现可信？

程序跑通、产物完整、结果导出与科学有效性是不同层次。论文配置一致性、指标选择、数据泄漏与可重复性可另行审查，不增加为自动流程的科学验收门。

最小验收清单

  • 关闭 TUI 后任务保持服务托管，重连可看到历史、阶段与运行进程。
  • queue 与 steer 不混淆；停止当前子 Agent 不误停其他实验。
  • 同一 requestId 重复提交只接受一次；多客户端不重复训练。
  • 模型消息按 Session 隔离，外部网页内容按文本显示，不当成 HTML 执行。
  • 评测失败、分数非有限、覆盖不足或双路径导出失败都阻止“正式完成”。
  • Goal/Todo/Team 展示源于真实状态；暂定指标与正式得分有明确区分。
