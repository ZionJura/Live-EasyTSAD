EasyTSAD Harness · 自动复现流程

从论文与官方仓库到 EasyTSAD 方法、真实训练评测和已有结果文件。当前默认模型：deepseek-v4.1-flash。完整的原版 DSH 源码教程与配置检索保留在 从零理解 DeepSeek Harness。

每篇论文独立推进

控制器持久保存任务阶段、研究分支、进程与进度。点击阶段查看具体工作；三个研究分支并行运行。

DIAGNOSE 仅在具体执行异常出现后介入，读取进程、日志与源码证据，修复后继续。低分本身不是失败条件。没有强制 SMOKE 或人工审核阶段。

RESEARCH 同时完成三件事

超参数

research-hyperparameters

从论文和官方源码提取参数、有效默认值与来源证据。

产物：config.toml、reproduction/hyperparameters.json。

接口适配

research-interface

映射训练输入、窗口、维度、分数方向与时间位置，保留原算法语义。

产物：reproduction/adapter.yaml，含 source、target、align、evidence。

运行环境

research-environment

研究官方依赖，控制器脚本执行 uv 锁定、安装和导入验证。

产物：environment/pyproject.toml、uv.lock、环境证据与安装日志。

加上 FETCH 的 fetch-repository，一共四个通用技能。IMPLEMENT 与 DIAGNOSE 使用固定提示词；协调、监控与报告由控制器处理。没有官方仓库时标为 unsupported，不凭论文重新编造算法。

聊天与流程分别运行

简洁 TUI 终端命令框读取会话、任务、阶段和进度；/ps 查看进程。Harness 不再提供网页交互，React 榜单独立展示已导出结果。
常驻 Host 普通对话、Slash、queue、steer 和停止当前回复；重连后恢复会话。
独立 CLI Worker FETCH、三个 RESEARCH 分支和 IMPLEMENT 等使用各自的 CLI 会话，绑定 kind=cli，有独立 PID、日志、历史、后续消息和取消入口。
Python 控制器 决定阶段、启动受管理进程、安装环境、调度训练和评测、读取 canonical 结果。
已有 EasyTSAD 流程 方法适配器、数据和实验评测；结果直接落在 Results/Evals。

常驻 Host 只使用 dsh-base 与原生会话控制后端，不加载原版 dsh-web-app、浏览器 UI 或 Webserver。完整上游教程中的 Web / Desktop 章节介绍原版能力，不代表本项目启用了网页。

流程 Worker 的 MCP 连接

每轮 CLI Worker 启动前，控制器先预启动该角色的受限 MCP 服务，等待就绪后使用 loopback Streamable HTTP 连接。服务只监听 127.0.0.1，端口与秘密路径每轮随机生成；冷启动导入不占用原版客户端的 60 秒 MCP 握手窗口。服务与 CLI 分别记录 PID、身份和日志，随本轮结束而停止；/ps 和 API 展示会移除秘密路径。

固定 rc1 与 Team 任务板

Host 固定为 npm 0.2.2-rc.1。该发布版本没有原生 Team 包；当前 Team 由项目内的 team-adapter.mjs 提供，状态原子保存在 DSH_HOME/tsad-team-boards.json。每个会话树最多 256 条任务，支持 revision 检查、依赖关系与领取/完成状态；Lead 使用 tsad_team，客户端读取 snapshot.team。健康接口明确返回 teamImplementation: tsad-adapter。实验调度继续由 Python 控制器负责。

运行状态必须有实际记录

入口能看到什么
任务流程FETCH → RESEARCH → IMPLEMENT → EVALUATE → REPORT → DONE，三个分支的状态与产物、实际参数。
训练 / 评测进度训练 epoch 或实际计数、评测已完成 / 总量、当前数据集与曲线；无记录时显示等待。
/ps [job] / 进程面板Agent、环境安装和评测进程的 PID、启动时间、argv、工作目录、GPU、日志路径、脚本路径及脚本内容。
会话Host 与 CLI Worker 的历史、queue / steer 消息和独立停止回复。
结果canonical avg.json / all.json 的路径与原始指标数据；进行中的结果为 provisional，完成后为 final。

REPORT 直接返回已有结果

每个数据集的 avg.json 保存汇总，all.json 保存逐曲线指标。它们由既有评测生成，API 与 TUI 直接读取。REPORT 返回引用和数据，不额外要求 Markdown 报告、不复制指标文件、不再算一套指标。

GET /api/harness/v1/jobs/{id}            # branches / progress / processes
GET /api/harness/v1/processes?jobId=...   # PID / argv / cwd / log / scriptContent
GET /api/harness/v1/jobs/{id}/scores     # avg/all 原始指标
GET /api/harness/v1/jobs/{id}/report     # avg/all 引用与数据
GET /api/harness/v1/events               # 实时事件

/ps [job]                               # 同一份进程信息
