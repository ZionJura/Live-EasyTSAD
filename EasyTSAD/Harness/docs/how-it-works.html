EasyTSAD Harness — how it works

Automated reproduction of time-series anomaly detection papers as EasyTSAD methods, evaluated by the existing LiveLeaderBoard pipeline. State as of 2026-11-05 (v0.1, initial simplified framework).

1. One task = one paper = one method

The harness owns the control flow as a deterministic phase state machine, while the model writes the code. An LLM agent is only used inside three phases. The harness decides whether a phase is done by running machine checks, not the model. Click a phase for details.

2. Architecture

CLI scripts/harness → tsad_harness/cli.py (search, new, run, status, approve, correct, answer, log, guard, reset, report, publish, doctor)
TSAD domain layer (new) pipeline.py phase machine · task.py state + journal · validate.py exit checks · guard.py protected files · runner.py uv/exp integration · papers.py · report.py · review.py
TSAD tools for the agent tools.py, an MCP stdio server whose tools appear as mcp__tsad__* (contract, notes, import check, smoke run, ask human)
DeepSeek Harness (unchanged) the dsh --profile headless binary from PyPI, trimmed by dsh/trim.patch.yml: agent loop, sessions, compaction, bash/fs tools, MCP client, llm-pi-ai → YYT gpt-6.1-sol (Responses API)
Live-EasyTSAD (unchanged) EasyTSAD/Methods/<Name> · envs/<env> + envs/registry.toml (uv) · scripts/tsad exp · LiveLeaderBoard/results · leaderboard/ site

Four modules

① Paper search & download

  • arXiv API (direct connection), GitHub repo search (proxy), LLM web search fallback through the Responses API
  • PDF → paper.md with page markers (PyMuPDF)
  • Official code is cloned with git clone --depth 1 and its commit recorded

② Reproduction & evaluation

  • EVIDENCE → reproduction contract
  • IMPLEMENT: method folder plus a uv env (reuse torch2 or scripts/tsad new)
  • SMOKE: 2 NAB curves through the real pipeline
  • EVALUATE: unmodified scripts/tsad exp, run detached

③ Results & leaderboard

  • catalog.toml entry with paper metadata
  • scripts/tsad export → benchmark.json
  • report.md / REPRODUCTION.md
  • publish: copy to leaderboard/public, npm run build, optional deploy

④ Human correction & records

  • approve clears a review gate.
  • correct -m "..." [--phase P] stores the note together with a context snapshot (the last events, the git status of the method/env, and the last smoke result), optionally rewinds the phase, and injects the note at the top of the next agent prompt as HUMAN CORRECTIONS (highest priority).
  • answer replies to mcp__tsad__ask_human.
  • log prints the combined timeline.

3. What happens inside one agent phase

pipelinereload state, clear stale question flag, take the guard baseline (once per task)
pipelinebuild the prompt: phase template (+ any pending human corrections, + validator errors in repair rounds)
agent.pyrender <task>/dsh/runtime.patch.yml (LLM route, system prompt, session root, MCP server), then launch dsh --profile headless --patch trim --patch runtime --json [--session-id S] -
DSHmodel → tools → model loop: read/grep/glob/edit/write/bash + mcp__tsad__*; all events are persisted to the session JSONL
agent.pystream the NDJSON to dsh/runs/NNN-phase.ndjson; enforce budgets (steps, wall clock via watchdog); detect missing tools
pipelinereload state → guard check → pending question? → phase validator
pipelinevalidator fails: repair round with the exact errors (up to 4). Validator passes: next phase or review gate
PhaseExit check (validate.py)
EVIDENCEcontract schema, 9 required claim ids, a source for every explicit/inferred claim, epoch key rule
IMPLEMENTfiles and class name, src/ has no EasyTSAD imports, registered in exactly one env, config.toml matches the contract, import check inside the env, guard clean
SMOKElatest smoke run succeeded, scores are 1-D and finite, source hash unchanged since the run, guard clean
EVALUATEevery (method, dataset) run succeeded
REPORTmethod present in benchmark.json

A low metric is never a repair trigger.

4. DSH: what was kept and what was trimmed

DSH is not forked. The shipped headless profile is composed with one patch that disables 36 plugin rows. The source in EasyTSAD/tsautoreproduce-harness/ (upstream fcc0ad4621, git link removed) is kept for reference only.

Kept

  • agent loop (step/turn lifecycle, cancellation, LLM retry)
  • session + JSONL persistence (uncompressed, inside the task dir)
  • context compaction, tool-result pruning, spill
  • bash, jobs, fs read/write/edit, glob/grep, working directory
  • MCP client (TSAD tools), llm-pi-ai OpenAI-compatible route

Removed

  • DeepSeek session-log upload, telemetry, inventory reporting
  • DeepSeek-only model routes, LLM session titles
  • web search/fetch (paper retrieval is a deterministic step)
  • subagents, goal/plan/todo, workflow/PTC, skills
  • remote-access API gateway

6. Current status: first real task (DIFR — Deep Isolation Forest, arXiv 2206.06602)

PhaseResult
FETCHdone: 14-page PDF → paper.md; official code xuhongzuo/deep-iForest cloned at e77692b
EVIDENCEdone in about 8 min, 10 model steps, 41 tool calls, about 0.5 M tokens (83 % cache hits); contract valid on the first try
Review gatewaiting for a human: scripts/harness approve DIFR or scripts/harness correct DIFR -m "..."
IMPLEMENT → REPORTnot started

Contract produced by the agent

Claim statusCountMeaning
explicit12stated in the paper (with section, equation or table)
inferred33from the official code (file:line) or unambiguous context
unspecified2neither; neutral default recorded

Key values: window 100 (train stride 10, test stride 1), raw input, 50 random untrained dilated CNN representations × 6 isolation trees each, 256 samples per tree, no training (epochs 0, no optimiser), and DEAS score (paper Eq. 8) assigned to the window end. Thresholding is left to EasyTSAD.

Notes recorded: 4 deviations, where the official code differs from the paper and the paper is followed (forest-level vs. per-representation score averaging, zero deviations included in the mean, no leaf path-length correction, no label-based segment adjustment). It also recorded 3 assumptions and 1 issue (per-call representation standardisation in the official code).

Problems found and fixed while getting here

  • MCP tools missing. On the networked filesystem, the cold import mcp takes about 50 s, which is longer than the MCP initialize timeout, so the agent ran without mcp__tsad__*. Fix: prewarm before launch, set a longer startup timeout, and fail fast when the tools are missing.
  • Wrong paper metadata in the prompt. The EVIDENCE prompt read the wrong meta.json keys and reported that no official code existed. This is fixed.
  • Network. The local proxy cannot reach YYT or arXiv, so those hosts are reached directly and GitHub goes through the proxy. The SOCKS all_proxy is dropped for DSH.
  • Code review. An independent review with adversarial verification confirmed 20 bugs. These include lost state updates between processes, approve skipping phases, a guard baseline that silently absorbed violations, a re-launched evaluation, the API key reaching bash children, and a wall-clock budget that a silent process could escape. All 20 are fixed: per-task lock with reloads, gated approve (--force is logged), a one-time guard baseline with guard --restore/--accept, eval re-attach, a key scrubbed from child processes, and a watchdog timer.
